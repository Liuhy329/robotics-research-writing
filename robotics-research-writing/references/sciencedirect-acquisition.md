# ScienceDirect 检索、合法下载与归档

用户要求获取 ScienceDirect 文献时读取；仅处理本地文献时跳过。该流程和脚本提供获取方法，不提供账户、订阅权限或预先下载的文献。

## 入口与访问

1. 根据当前任务确认主题、年份与篇数。先在个人来源索引及资料库按 DOI、题名和版本去重，复用已有完整原件。
2. 检查当前可用的检索、下载与浏览器 skill，并遵守其实际接口。记录查询、筛选条件、实际查看范围与入选理由，不将搜索总命中数写成阅读数。
3. 用户指定浏览器或已完成机构登录时复用其现有会话。登录或真人验证由用户完成，Codex 不读取、保存或输出密码、验证码、cookies 或账户存储。普通出版者个人账户不等于机构订阅权限。
4. 检查实际全文或 PDF 访问状态；仅取得 OA 文献不能证明机构订阅有效。缺少机构会话时使用合法公开全文入口，不声称拥有订阅权限。
5. 认证过期、验证码、权限拒绝或访问策略拦截时停止相应获取，不借传输脚本绕过。只记录稳定来源页、阶段、文件状态及下一步，不保存临时签名或认证数据。

## 从实际页面取得 PDF

- 在当前文章页读取真实 PDF 入口，核对 PII 与本篇匹配；参考文献中的 PDF 链接不能冒充正文入口。沿正常浏览器跳转检查最终状态。
- `pdf.sciencedirectassets.com` 的地址必须来自本次合法浏览器跳转，不猜测签名、过期时间或 PII。签名地址过期后回文章页重新取链。
- PDF 阅读器已显示时可传输其实际地址；阅读器未渲染但正常入口已返回真实 PDF 地址且无验证、拒绝或策略拦截时，可对该地址做一次传输和内容核验。地址栏出现 CDN 地址本身不证明文件有效。
- 仅使用页面明确列出的 `ars.els-cdn.com` PDF 附件。不猜测附件编号；普通补充材料不能冒充主文。正文加补充材料的合并版标为 `article-with-SI`，独立附件标为 `supplement`。
- 不能获取合法完整来源时保留断点，继续本次任务中不依赖该篇的工作，不将部分 PDF 计为完成。

## 本地下载脚本

[sciencedirect_download.py](../scripts/sciencedirect_download.py) 需要 Python 3.9+、`pypdf` 与系统 `curl.exe` 或 `curl`。脚本不控制浏览器，不登录，不导出 cookies，也不刷新签名。必须显式传入资料目录，不能依据 skill 安装目录推定保存位置。

由执行任务的 Codex 在本地生成专用临时请求 JSON，字段来自本次实际页面或请求，不要求用户手工整理：

| 字段 | 含义 |
|---|---|
| `pii` | 文章页面核实的 PII |
| `url` | 本次观察到且仍有效的 PDF 地址；属于临时授权材料，不公开展示 |
| `headers` | 仅实际请求的 `User-Agent` 和对应文章页 `Referer` |
| `role` | `main`、`article-with-SI` 或 `supplement`，默认 `main` |

在 skill 目录调用（替换成当前任务的实际路径）：

```text
python scripts/sciencedirect_download.py --request /path/to/temporary-request.json --library-dir /path/to/research/.robotics-writing/literature --route system-proxy
```

`system-proxy` 沿用现有 HTTPS 代理，不改全局设置。已合法取得的实际地址因传输问题失败且没有访问验证或拒绝时，可以尝试一次 `--route direct`；该参数仅为本次 curl 指定 IPv4、TLS 1.2 上限并绕过显式代理，仍验证证书。它不保证绕过系统隧道或网络路由；不把单次成功解释为确定故障原因。

脚本先保存 `PII-role.pdf.part`；HTTP/PDF 结构、可解析页数和加密状态检查通过并记录 SHA-256 后改为 `.pdf`。已有同名 PDF 拒绝覆盖。`pdf_structure_valid_identity_pending` 表示结构通过，题名/DOI 身份尚待核验。非敏感日志写在资料目录的 `下载记录/`，专用请求 JSON 在尝试结束后删除；不要公开日志或文献。

## 有限恢复与停止

- 连接上限 30 秒，连续 30 秒速率低于 1 字节/秒中止，单次传输上限 1800 秒。HTTP 200 仍须检查 PDF；HTML 准备页和验证页不算成功。
- 正文签名 PDF 从头传输；公开附件可顺序续传，最多 2 次重试。继续附件前确认 `.part` 对应同一实际文件与版本；来源不明时保留诊断副本并从头开始。curl 核验续传支持，不并发拼片。
- 登录失效或安全验证交给用户完成；网络错误与账户无权限分开。浏览器打开、下载触发和本地落盘分别记录。
- 正常路线的有限重试失败，且另一条实际可用的合法路线也失败时停止该篇。没有合并版时不猜测替代附件，不无限重试。

## 核验与交付

1. 先转 Markdown，再将题名、作者、DOI、期刊、日期与稳定文章页核对；保留 online date、期次日期及版本区别。关键图表及转换异常回看原页。
2. 按核实题名重命名，版本或合并材料加必要后缀；重名比对哈希，不覆盖。分类遵循用户资料库，没有分类时先按标题存放。
3. 更新个人来源索引：稳定编号、路径、版本、角色、页数、哈希、来源页、获取日期与实际阅读范围。区分“已获取待核验”“已核验待阅读/蒸馏”“已阅读/蒸馏”。
4. 只下载时交付实际归档结果；已有蒸馏授权时返回 SKILL.md 模式 A。PDF、附件、独立研究与实际阅读范围分别报告，不隐式创建定时任务。
